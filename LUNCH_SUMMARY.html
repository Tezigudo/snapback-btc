5. ⚠️ Validation finding — port has signal drift (DO NOT DEPLOY YET)

Ran tools/validate_v3_port.py on a 3-month window (Oct-Dec 2025) comparing live-port signal fires to backtest entries. Result: 0% timestamp overlap.
SourceEntries / signal fires
Backtest (V3AllWider4)13
Live port (this hour)6
Common timestamps0

Root cause analysis — two issues:

  1. Off-by-one bar (timing report): backtest records EntryTime as the fill time (= open of bar i+1 with trade_on_close=False). Live port returns the signal at the moment the bar closes (= start of bar i+1). They're 15 minutes apart, so set intersection is empty. Example: backtest entry at 2025-10-03 07:45, live fires at 2025-10-03 07:30 — same event, different timestamp convention.
  2. Real signal-count drift: backtest = 13 entries, live = 6. After fixing the timing issue, ~5 entries are likely lost. Possible causes (need investigation):
    • Daily ATR percentile computation slightly differs (rolling-window edge effects)
    • Position-already-open logic: backtest tracks an open position so it doesn't re-enter; my port doesn't know about position state and may suppress some entries the backtest takes after close
    • TA confirmation slicing — swing detection uses different effective window boundaries

What this means: the port produces FEWER signals than the backtest. It's "more conservative" — likely safer, but the live returns will be LOWER than the backtest predicts. Until we resolve this, DO NOT deploy v3-all-wider-4 live. Keep dry-running v1.
